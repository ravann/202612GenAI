# RB-01 VPN connection troubleshooting

Applies to the VPN gateways `vpn-gw-01` (dc-east) and `vpn-gw-02` (dc-west). Both sit behind the perimeter firewall `fw-01` and authenticate users against the identity provider `idp-01`.

## Before you start

- Ask for the exact error code shown by the VPN client and the user's office.
- Check whether other users in the same office are affected. One user is a client problem; a whole office is usually a network or certificate problem.
- Check the open incidents for the `vpn-gateway` service before you change anything.

## Error VPN-809: TLS handshake failed

1. Open the gateway status page and check the certificate expiry date on the affected gateway.
2. If the server or intermediate certificate has expired, renew it from the certificate vault and restart the VPN service on that gateway only.
3. Ask one affected user to reconnect. The handshake should complete in under 5 seconds.

## Error VPN-691: credentials rejected

1. Confirm that the user can sign in to another single sign-on application. If not, follow RB-02 (account lockout).
2. If sign-in works elsewhere, check that the user is in the `vpn-users` directory group.
3. Delayed MFA pushes from `idp-01` also show as VPN-691 after 60 seconds. Check the identity provider status before you escalate.

## Error VPN-1203: client update failed

1. The client downloads its update package from the gateway. Check that the package on the gateway is signed.
2. Re-publish the signed package and ask the user to restart the client.

## Whole office cannot reach a gateway

1. Check `fw-01` for recently changed rules that cover the office's network range.
2. Fail the office over to the other gateway while you investigate.
3. Raise the incident to P2 if more than 25 users are affected (see RB-09).
