# RB-08 Slow CRM customer search

The CRM runs on `web-crm-01` and `app-crm-01`. Customer data lives in the orders database `db-04`, which the CRM shares with checkout. Sign-in uses `idp-01`.

## Symptoms

- Customer search takes more than 5 seconds, or times out after 30 seconds.
- The CRM log on `app-crm-01` shows `SEARCH-TIMEOUT` entries.

## Step 1: is it the search index or the database?

1. Run the same search twice. If the second run is fast, the index cache was cold; no action needed.
2. Check the index status page. An index older than 7 days, or in state `degraded`, needs a rebuild.
3. If the index is healthy, check `db-04` for slow queries (see RB-04, step 3). A slow `db-04` also slows checkout.

## Step 2: rebuild the index

A rebuild takes about 40 minutes and puts extra read load on `db-04`. It is a change (RB-05): raise a change request and run it in a change window, never during the checkout peak.

## Step 3: reporting jobs

The job `crm-nightly-report` must run between 01:00 and 05:00 UTC. If it runs during the day, stop it and inform the CRM team; it competes with checkout for `db-04`.
