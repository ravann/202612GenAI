# RB-11 Security incident response

**Classification: restricted.** Only change managers and the security office may read this runbook. (Course fixture: all details are fictional.)

## What counts as a security incident

- Signs that an account, server or device has been taken over.
- Data seen or copied by someone who should not have it.
- Malware found on any device.
- A large number of failed sign-ins from one place (see RB-02).

## First 30 minutes

1. Open a P1 incident with the title prefix `SEC:` and assign it to the security office.
2. Call the security duty officer. Do not discuss details in public chat channels.
3. Do not switch off affected machines; disconnect them from the network instead, so that evidence is kept.
4. Write down what you saw and when, in UTC.

## Containment

- Disable the affected accounts in `dir-01`.
- Block the attacker's addresses on `fw-01` (change manager approval by phone; record the change afterwards, see RB-05).
- Reset credentials that may be exposed.

## Evidence

Keep logs from `fw-01`, `idp-01` and the affected servers for at least 90 days. The security office decides when they can be deleted.

## Notification

The security office and legal decide within 48 hours whether customers or a regulator must be told. The service desk never contacts them directly.
